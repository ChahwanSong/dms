DM 데이터 잡 · 프리뷰 / 컨펌 워크플로
뮤테이션 잡(sync · rm)은 프리뷰 지문이 확인된 뒤에만 실행된다 · scan 은 읽기전용이라 프리뷰를 건너뛴다
PHASE 1 · 프리뷰 (dm-worker)
claim_plan · phase = preview
CAS 점유 + 리스 · data_job 로드
↓
아이덴티티 해석 · fail-closed (캐시 없음)
POSIX 실행 신원을 확정한다
1
거부목록
denylist 우선 → 차단 시 REJECTED
2
특권 분기
allow_root + owner∈privileged → uid/gid 0 (LDAP·플로어 스킵)
3
LDAP 조회
읽기전용 · uid / gid / 그룹
4
uid·gid 플로어
<1000 거부 · root 포드 내 runuser 격리
↓
후보 노드 선정 · Fresh 에이전트 리포트만
마운트 ✓ 툴 ✓ 자격증명 ✓ 아이덴티티 ✓ · sync: 동일노드→dsync / 분리→nsync
↓
Volcano 프리뷰 MPI 잡 · --dryrun
제출 즉시 job_ref 기록(취소 대비) · 산출물에서 지문 계산
↓
data_job → CONFIRM_PENDING · preview_expires_at
지문 저장 · run 을 BLOCKED 상태로 파킹 (컨펌 대기 센티넬)
↓  운영자 / 포탈이 프리뷰를 확인
confirm_data_job · POST /jobs/{id}:confirm
confirm = true requester 일치 프리뷰 미만료 지문 일치 (dm_confirm_require_preview_fingerprint)
통과 → data_job CONFIRMED · plan/request 를 PLANNED 로 되돌려 재점유 가능 · 파킹된 run 종료
↓
PHASE 2 · 실행 (dm-worker 재점유)
claim_plan · phase = execution
되돌려진 플랜을 다시 점유
↓
프리플라이트 재검증 · execution_recheck
프리뷰~컨펌 사이 아이덴티티·후보 변화 대비 (fail-closed)
↓
SCHEDULED → RUNNING · Volcano 실 MPI 잡
dsync / drm / nsync · --dryrun 없음
↓
VERIFYING → SUCCEEDED ✓
관측 phase 확인(TimedOut→TIMED_OUT / 실패→FAILED) · upsert_resource · complete_result
↓
scan 은 읽기전용 → 프리뷰/컨펌 없이 PHASE 2 로 직행한다.   data.cancel 은 실행 중 MPI 잡을 먼저 종료하고(종료 실패 시 거짓 취소를 보고하지 않음) 그 뒤에 CANCELLED 로 기록한다.

## 4. mTLS 인증서 및 API token

모든 인증서는 `/mgmt_storage/cocoa.song/.dms-secrets/certs/`에 저장된다. 재설치 시 아래 명령으로 재생성한다.

```bash
CERTS=/mgmt_storage/cocoa.song/.dms-secrets/certs
mkdir -p $CERTS

# Client CA (ingress mTLS 검증용)
openssl req -x509 -newkey rsa:4096 -nodes -days 3650 \
  -keyout /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-client-ca.key \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-client-ca.crt \
  -subj "/CN=dms-client-ca/O=pvs-dms"

# Server CA + server cert (dms.pvs-dms.local)
openssl req -x509 -newkey rsa:4096 -nodes -days 3650 \
  -keyout /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-server-ca.key \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-server-ca.crt \
  -subj "/CN=dms-server-ca/O=pvs-dms"

openssl req -newkey rsa:2048 -nodes \
  -keyout /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-api-server.key \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-api-server.csr \
  -subj "/CN=dms.pvs-dms.local/O=pvs-dms"

echo "subjectAltName=DNS:dms.pvs-dms.local" > /mgmt_storage/cocoa.song/.dms-secrets/certs/san.ext
openssl x509 -req -days 3650 \
  -in /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-api-server.csr \
  -CA /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-server-ca.crt \
  -CAkey /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-server-ca.key \
  -CAcreateserial -extfile /mgmt_storage/cocoa.song/.dms-secrets/certs/san.ext \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-api-server.crt

# Operator client cert
openssl req -newkey rsa:2048 -nodes \
  -keyout /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.key \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.csr \
  -subj "/CN=operator/O=pvs-dms"

openssl x509 -req -days 3650 \
  -in /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.csr \
  -CA /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-client-ca.crt \
  -CAkey /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-client-ca.key \
  -CAcreateserial \
  -out /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.crt
```

| 파일 | 용도 |
|---|---|
| `dms-client-ca.crt` | ingress mTLS client 검증 CA (`dms-client-ca` Secret) |
| `dms-server-ca.crt` | curl `--cacert`용 server CA |
| `dms-api-server.crt/key` | ingress TLS server cert (`dms-api-tls` Secret) |
| `operator.crt/key` | DMS API 호출용 operator client cert |

**API token**: `df5bfac061d52983450a6b92e1429825542aa641c44d9aadb7218050438aa28b`

## 5. SSH backend credential

RM Worker가 CephFS quota 명령(`setfattr`/`getfattr`)을 ion 노드의 root 계정으로 실행한다.

```bash
# rts2411에서 key 생성
ssh rts2411 'ssh-keygen -t ed25519 -f /mgmt_storage/cocoa.song/.dms-secrets/dms-backend-ssh -C dms-rm-worker -N ""'

# 모든 ion 노드 root 계정에 등록
for node in ion2401 ion2402 ion2403 ion2404 ion2405 ion2406; do
  PUBKEY=$(ssh rts2411 'cat /mgmt_storage/cocoa.song/.dms-secrets/dms-backend-ssh.pub')
  ssh $node "sudo mkdir -p /root/.ssh && echo '$PUBKEY' | sudo tee -a /root/.ssh/authorized_keys > /dev/null && sudo chmod 600 /root/.ssh/authorized_keys"
done

# known_hosts 수집
ssh rts2411 'ssh-keyscan -H ion2401 ion2402 ion2403 ion2404 ion2405 ion2406 > /mgmt_storage/cocoa.song/.dms-secrets/dms-known_hosts'
```

private key, known_hosts, SSH config는 `dms-ssh-client` Secret에 포함된다.

## 9. Storage mapping 등록

Storage mapping은 DMS API로 직접 등록한다. DB가 source of truth이며 별도 파일을 유지하지 않는다. 현재 등록된 목록은 언제든 `GET /api/v1/operations/storage-mappings`로 조회할 수 있다.

```bash
source /mgmt_storage/cocoa.song/.dms-secrets/dms-env.sh

# cephfs-pvs-dms
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/storage-mappings" \
  -d '{
    "storage_name": "cephfs-pvs-dms",
    "backend_template": {
      "backend_type": "cephfs",
      "cluster_name": "pvs-dms",
      "mount_path": "/mgmt_storage",
      "managed_root": "/mgmt_storage/root",
      "rm_worker_nodes": ["ion2401","ion2402","ion2403","ion2404","ion2405","ion2406"],
      "ssh_host": "ion2401",
      "csi_driver": "rook-ceph.cephfs.csi.ceph.com"
    },
    "cluster_name": "pvs-dms",
    "storage_class_name": "rook-cephfs"
  }' | jq '{storage_name, status}'

# gpfs-pvs-dms
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/storage-mappings" \
  -d '{
    "storage_name": "gpfs-pvs-dms",
    "backend_template": {
      "backend_type": "gpfs",
      "cluster_name": "pvs-dms",
      "filesystem_name": "pvs",
      "mount_path": "/pvs",
      "managed_root": "/pvs",
      "fileset_root": "/pvs/dms",
      "rm_worker_nodes": ["ion2404","ion2405","ion2406"]
    },
    "cluster_name": "pvs-dms"
  }' | jq '{storage_name, status}'

# weka-pvs-dms
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/storage-mappings" \
  -d '{
    "storage_name": "weka-pvs-dms",
    "backend_template": {
      "backend_type": "wekafs",
      "cluster_name": "pvs-dms",
      "filesystem_name": "pvs_weka",
      "mount_path": "/pvs_weka",
      "managed_root": "/pvs_weka/dms",
      "rm_worker_nodes": ["ion2402","ion2403"]
    },
    "cluster_name": "pvs-dms"
  }' | jq '{storage_name, status}'
```

> **WEKA 백엔드 주의사항:**
> - `weka fs quota set/list/reset` CLI는 cluster 인증 필요 (`weka user login` 또는 `WEKA_USERNAME`/`WEKA_PASSWORD`/`WEKA_ORG` 환경변수). 인증 안 된 RM worker에서 quota 작업 시 `BackendPreconditionError: WekaFS quota CLI not authenticated` 발생.
> - WEKA path quota는 capacity_bytes만 지원. `file_count`(inode quota) 미지원 — 지정 시 backend가 명시적으로 거절.
> - WEKA CSI 드라이버(`csi.weka.io`)는 현재 pvs-dms 클러스터에 미설치. CSI 매핑 자체는 코드에 등록되어 향후 검증 가능.

- `cluster_exists`: Passed
- `storage_class_exists`: Passed
- `csi_driver_matches`: Passed

## 10. Agent DaemonSet 배포

파일: `/mgmt_storage/cocoa.song/.dms-secrets/dms-agent-daemonset.yaml` (backup: `.dms-secrets/dms-agent-daemonset.yaml`)

### 10.1 주요 설정값

| 키 | 값 |
|---|---|
| `DMS_AGENT_API_URL` | `http://dms-api.dms.svc.cluster.local:80` |
| `DMS_AGENT_CLUSTER_NAME` | `pvs-dms` |
| storage | `cephfs-pvs-dms`, mount_paths: `[/mgmt_storage]` |
| image | `rts2411:5000/dms:9e3bfb7` |

### 10.2 트러블슈팅 및 수정사항

**1) control-plane 노드(ion2401) toleration 추가**
DaemonSet에 control-plane NoSchedule taint toleration이 없어 ion2401에 pod가 미배포됨.
```bash
kubectl -n dms patch daemonset dms-rm-agent --type=json -p '[{"op":"add","path":"/spec/template/spec/tolerations","value":[{"key":"node-role.kubernetes.io/control-plane","operator":"Exists","effect":"NoSchedule"}]}]'
```

**2) Agent API URL 변경**
agent가 `dms.pvs-dms.local`을 DNS 조회할 수 없음 (pod 내부에서 /etc/hosts 미참조).<br>
`DMS_AGENT_API_URL`을 cluster-internal Service URL로 변경:
```bash
kubectl -n dms set env daemonset/dms-rm-agent DMS_AGENT_API_URL=http://dms-api.dms.svc.cluster.local:80
```

**3) mTLS 헤더 비활성화**
Agent는 ingress를 우회해 직접 API에 접근하므로 mTLS 헤더를 제공할 수 없음.<br>
`DMS_REQUIRE_MTLS_HEADER=false`, `DMS_REQUIRE_MTLS_VERIFIED_HEADER=false`로 변경.<br>
내부 보안은 NetworkPolicy + Bearer token으로 유지.
```bash
kubectl -n dms patch configmap dms-runtime-config --type=merge -p '{"data":{"DMS_REQUIRE_MTLS_HEADER":"false","DMS_REQUIRE_MTLS_VERIFIED_HEADER":"false"}}'
kubectl -n dms rollout restart deployment/dms-api
```

**4) NetworkPolicy 추가**
agent → dms-api(port 8080) 직접 접근을 허용하는 NetworkPolicy 추가:
```bash
kubectl -n dms apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: dms-api-from-agent
  namespace: dms
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: dms-api
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app.kubernetes.io/name: dms-rm-agent
      ports:
        - protocol: TCP
          port: 8080
EOF
```

### 10.3 API 인증 주의사항

`DMS_REQUIRE_MTLS_HEADER=false` 상태에서 외부 API 호출 시 Bearer token + `x-dms-actor` 헤더가 모두 필요:
```bash
curl -sS \
  --cert /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.crt \
  --key /mgmt_storage/cocoa.song/.dms-secrets/certs/operator.key \
  --cacert /mgmt_storage/cocoa.song/.dms-secrets/certs/dms-server-ca.crt \
  -H "authorization: Bearer df5bfac061d52983450a6b92e1429825542aa641c44d9aadb7218050438aa28b" \
  -H "x-dms-actor: operator" \
  https://dms.pvs-dms.local:30535/api/v1/...
```

### 13.3 등록 (POST)

**backend_template 필드:**

| 필드 | 필수 | 설명 |
|---|---|---|
| `backend_type` | 필수 | `cephfs`, `gpfs`, `wekafs` 지원 |
| `cluster_name` | 필수 | DMS 클러스터 이름 |
| `mount_path` | 필수 | 각 노드에 마운트된 절대 경로 |
| `managed_root` | 필수 | DMS가 관리하는 루트 디렉터리 (mount_path 하위). cephfs/wekafs는 `mount_path/dms`를 기본값으로 사용 |
| `filesystem_name` | wekafs/gpfs | WEKA/GPFS filesystem 이름 (예: `pvs_weka`, `pvs`) |
| `fileset_root` | gpfs | GPFS fileset junction이 위치할 디렉터리 |
| `rm_worker_nodes` | 권장 | RM 작업 대상 노드 목록. Agent가 이 노드들에서 마운트 증거를 수집해 `rm_readiness` 판단에 사용 |

| `csi_driver` | 선택 | Kubernetes PVC provisioning용 CSI 드라이버. 생략 시 `csi_driver_matches` sanity check 제외. backend_type에 따라 기본값 적용: `cephfs`→`rook-ceph.cephfs.csi.ceph.com`, `gpfs`→`spectrumscale.csi.ibm.com`, `wekafs`→`csi.weka.io` |

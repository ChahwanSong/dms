# DMS Resource Management API — Kubernetes Namespace Quota

최초 작성: 2026-06-15

DMS의 **Kubernetes namespace quota** Resource Management API를 다룬다. Filesystem(GPFS/WekaFS/
CephFS) RM API는 [`2.dms-rm-api-fs.md`](2.dms-rm-api-fs.md), 설치 전체 과정은
[`1.install-dms-on-pvs.md`](1.install-dms-on-pvs.md)를 참조한다.

---

## 환경 변수 로드

모든 curl 예시는 아래를 먼저 실행한 상태를 전제로 한다 (`2.dms-rm-api-fs.md`와 동일).

```bash
source /mgmt_storage/cocoa.song/.dms-secrets/dms-env.sh
```

`DMS_CURL_OPTS` 배열에 `--resolve`, `--noproxy`, mTLS 인증서, Bearer token, `x-dms-actor` 헤더가 포함된다.

## 1. 동작 모델

DMS는 하나의 namespace quota 리소스를 대상 클러스터의 **단일 `ResourceQuota/dms-storage-quota`**
오브젝트로 렌더링한다.

- **대상 오브젝트**: `<namespace>/dms-storage-quota` (DMS 전용; 이름 고정)
  - 라벨 `dms.io/resource-kind: kubernetes-namespace-quota`
  - 어노테이션 `dms.io/resource-key: <cluster_name>:<namespace_name>`
- **`spec.hard` 키 매핑**:
  | DMS payload | ResourceQuota hard key |
  |---|---|
  | `quota.requests_storage_bytes` | `requests.storage` (namespace-wide) |
  | `quota.pvc_count` | `persistentvolumeclaims` (namespace-wide) |
  | `storage_class_quotas[].requests_storage_bytes` (또는 `capacity_bytes`) | `<sc>.storageclass.storage.k8s.io/requests.storage` |
  | `storage_class_quotas[].pvc_count` | `<sc>.storageclass.storage.k8s.io/persistentvolumeclaims` |
  - `requests.storage`는 bytes → k8s quantity(`Mi`/`Gi`)로 렌더링된다.
  - **최소 1개 hard key**가 있어야 한다(namespace-wide `quota` 또는 `storage_class_quotas[]` 중 하나 이상).
- **StorageClass 유도**: `storage_class_quotas[].storage_name`은 등록된 storage mapping에서
  `storage_class_name` + `cluster_name`을 derive한다(§2). 즉 호출자는 storage class 이름을 직접
  쓰지 않고 storage mapping 이름(`storage_name`)을 참조한다.
- **클러스터 라우팅**: payload의 `cluster_name`으로 `dms-cluster-kubeconfigs` Secret의 해당
  kubeconfig를 골라 그 클러스터의 API server에 ResourceQuota를 apply/read한다.
- **read-only / 비파괴 원칙**:
  - DMS는 자기 `dms-storage-quota`만 관리한다. namespace 내 **non-DMS ResourceQuota는 변경하지
    않고**, effective quota 경고(아래)만 기록하며, DMS delete 시에도 보존한다.
  - DMS lifecycle delete는 **namespace를 삭제하지 않는다**(ResourceQuota만 제거).

## 2. 사전 설정 — storage mapping 등록 (CSI StorageClass)

namespace quota의 `storage_class_quotas[].storage_name`이 가리킬 storage mapping을 등록한다.
backend type과 무관하게 **`cluster_name` + `storage_class_name`** 만 있으면 namespace quota에
사용할 수 있다(filesystem RM과 mapping을 공유한다).

```bash
source /mgmt_storage/cocoa.song/.dms-secrets/dms-env.sh

curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/storage-mappings" \
  -d '{
    "storage_name": "longhorn-a",
    "backend_template": {
      "backend_type": "longhorn",
      "csi_driver": "driver.longhorn.io"
    },
    "cluster_name": "cluster-a",
    "storage_class_name": "longhorn"
  }' | jq '{storage_name, status}'
```

| 필드 | 설명 |
|---|---|
| `storage_name` | namespace quota가 참조할 mapping 이름 |
| `cluster_name` | ResourceQuota를 적용할 대상 클러스터(= kubeconfig key) |
| `storage_class_name` | live StorageClass 이름 (hard key prefix로 사용) |
| `backend_template.csi_driver` | live StorageClass의 provisioner와 일치해야 sanity Ready |

> sanity가 storage class/`csi_driver`를 live StorageClass와 대조한다(불일치 시 readiness 저하).
> 같은 mapping을 filesystem RM과 공유하려면 `backend_type`/mount 등 filesystem 필드도 채운다
> (예시는 `2.dms-rm-api-fs.md`). namespace quota만 쓰는 경우 위처럼 CSI 필드만으로 충분하다.

대상 클러스터의 DMS ServiceAccount는 해당 namespace의 `resourcequotas`에 대해
`get/list/create/update/patch/delete` 권한이 필요하다(설치 시 RBAC로 부여; `1.install-dms-on-pvs.md`).

## 3. Namespace Quota Resource Management API

### 3.1 API 엔드포인트 요약

| Method | Path | Behavior |
|---|---|---|
| `POST` | `/api/v1/resource-management/kubernetes/namespace-quotas` | 신규 생성: `dms-storage-quota` ResourceQuota apply (+ read-back) |
| `PATCH` | `/api/v1/resource-management/kubernetes/namespace-quotas/{cluster}/{namespace}` | 부분 변경: `quota` / `storage_class_quotas[]`(full replacement) / `expires_at` / `resource_type` |
| `POST` | `…/{cluster}/{namespace}:block` | 차단/해제: `{"block": true}` 모든 hard를 `0`으로(restore state 저장), `{"block": false}` 복원 |
| `DELETE` | `…/{cluster}/{namespace}` | DMS `dms-storage-quota`만 삭제(namespace/PVC/non-DMS RQ 보존) |
| `POST` | `…/{cluster}/{namespace}:check` | consistency check: DB desired vs live `spec.hard` + metadata drift (side-effect 없음) |
| `POST` | `…/{cluster}/{namespace}:sync` | live `spec.hard`를 역산해 DB `quota`/`storage_class_quotas[]` 갱신 (side-effect 없음) |
| `POST` | `…/{cluster}/{namespace}:import` | 외부에서 만든 ResourceQuota를 full-managed로 채택 |
| `POST` | `/api/v1/resource-management/kubernetes/namespace-quotas:audit` | read-only audit: DB↔live drift + metadata drift 구조화 (Kubernetes 변경 없음) |
| `POST` | `/api/v1/resource-management/kubernetes/namespace-quotas:expiration-sweep` | 만료된 quota 일괄 차단 (`scope`/`expired_before`/`dry_run`) |
| `GET` | `/api/v1/operations/kubernetes/namespace-quotas/{cluster}/{namespace}` | 단건 조회 (DB desired + live + effective warning) |
| `GET` | `/api/v1/operations/kubernetes/namespace-quotas/expiring` | 만료 임박/만료 목록 |

> 모든 mutating 엔드포인트는 `202 Persisted` 반환 후 비동기 처리. 최종 상태는
> `GET /api/v1/operations/requests/{id}`로 폴링한다(상태값/`resolve`는 `2.dms-rm-api-fs.md` §4.2/§5 공통).

### 3.2 Create (생성)

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas" \
  -d '{
    "requester_id": "cocoa.song",
    "payload": {
      "cluster_name": "cluster-a",
      "namespace_name": "team-alpha",
      "quota": {"requests_storage_bytes": 107374182400, "pvc_count": 50},
      "storage_class_quotas": [
        {"storage_name": "longhorn-a", "requests_storage_bytes": 53687091200, "pvc_count": 20},
        {"storage_name": "cephfs-a",   "requests_storage_bytes": 53687091200, "pvc_count": 30}
      ],
      "expires_at": "2027-01-01T00:00:00Z"
    }
  }' | jq '{request_id, status}'
```

**payload 필드:**

| 필드 | 필수 | 설명 |
|---|---|---|
| `cluster_name` | 필수 | 대상 클러스터(kubeconfig key) |
| `namespace_name` | 필수 | 대상 namespace |
| `quota.requests_storage_bytes` | 조건부 | namespace-wide 저장 용량 합 → `requests.storage` |
| `quota.pvc_count` | 선택 | namespace-wide PVC 수 → `persistentvolumeclaims` |
| `storage_class_quotas[]` | 조건부 | StorageClass별 quota 목록. **entry가 2개 이상이면 각 entry에 `requests_storage_bytes`(또는 `capacity_bytes`) 필수** |
| `storage_class_quotas[].storage_name` | 필수(entry) | 등록된 storage mapping 이름(→ SC/cluster derive) |
| `storage_class_quotas[].requests_storage_bytes` / `capacity_bytes` | 위 참고 | SC별 용량 → `<sc>.storageclass.storage.k8s.io/requests.storage` |
| `storage_class_quotas[].pvc_count` | 선택 | SC별 PVC 수 → `<sc>.storageclass.storage.k8s.io/persistentvolumeclaims` |
| `expires_at` | **필수** | 만료일(ISO8601). 생략 시 `Rejected` |
| `resource_type` | 선택 | `user`(기본)/`project`/`system`/`admin` (§3.9) |

> **조건부 필수**: `quota`와 `storage_class_quotas[]` 중 **최소 하나**로 hard key가 1개 이상 만들어져야
> 한다(둘 다 비면 reject). single-StorageClass는 `quota`만으로도, 또는 entry 1개만으로도 가능.

검증/거부(planner):

- `cluster_name`/`namespace_name` 누락, `storage_class_quotas`가 list 아님, `storage_name` 누락,
  중복 `storage_name`, 값이 0 이하 → `Rejected`.
- storage mapping의 `cluster_name`이 요청 `cluster_name`과 다르면 cross-cluster mismatch reject.
- 동일 resource(`{cluster}:{namespace}`)가 이미 존재(non-Deleted)하면 create reject → PATCH 사용.

**렌더링되는 `spec.hard` 예시** (위 요청):
```
requests.storage:                                          100Gi
persistentvolumeclaims:                                    50
longhorn.storageclass.storage.k8s.io/requests.storage:     50Gi
longhorn.storageclass.storage.k8s.io/persistentvolumeclaims: 20
cephfs-rwx.storageclass.storage.k8s.io/requests.storage:   50Gi
cephfs-rwx.storageclass.storage.k8s.io/persistentvolumeclaims: 30
```

### 3.3 PATCH (quota / storage_class_quotas / expires_at / resource_type 변경)

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X PATCH -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha" \
  -d '{
    "requester_id": "operator",
    "payload": {
      "quota": {"requests_storage_bytes": 214748364800, "pvc_count": 80},
      "storage_class_quotas": [
        {"storage_name": "longhorn-a", "requests_storage_bytes": 107374182400, "pvc_count": 40}
      ]
    }
  }' | jq '{request_id, status}'
```

- **`storage_class_quotas[]`는 full replacement**다 — PATCH에 보낸 목록이 통째로 새 상태가 된다
  (빠진 SC entry의 hard key는 제거됨). 일부만 바꾸려면 유지할 entry까지 모두 포함해 보낸다.
- **decrease guard**: 어떤 hard(`requests.storage`/`persistentvolumeclaims`/각 SC key)를 live
  `status.used` 아래로 낮추려 하면 `Rejected`(데이터 손실 방지). namespace-wide + StorageClass별
  `status.used`를 각각 확인한다.
- `expires_at`/`resource_type`만 단독 변경 가능(ResourceQuota 변화 없이 DB만 갱신).

### 3.4 차단 / 차단 해제 (`:block`)

namespace quota는 `:block` 하나로 차단/해제를 모두 처리한다(filesystem과 달리 별도 `:initialize`
없음). payload의 `"block"`(boolean)으로 방향을 지정한다.

```bash
# 차단 — 모든 hard key를 0으로(현재 hard는 restore_hard로 저장)
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha:block" \
  -d '{"requester_id": "operator", "payload": {"block": true}}' | jq '{request_id, status}'

# 차단 해제 — block_state.restore_hard로 복원
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha:block" \
  -d '{"requester_id": "operator", "payload": {"block": false}}' | jq '{request_id, status}'
```

- `block: true`는 모든 hard를 `0`으로 만들어 신규 PVC/용량 요청을 막는다(기존 사용량은 유지).
- `block: false`는 `block_state.restore_hard`에 저장된 직전 hard로 복원한다(저장 state 없으면
  `block_restore_state_missing`으로 reject).
- `resource_type`이 `system`/`admin`이면 차단 거부(`resource_type_cannot_be_blocked`).
- blocked 상태에서도 PATCH로 desired hard는 갱신 가능(복원 시 새 값 반영).

### 3.5 삭제 (DMS ResourceQuota 제거)

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X DELETE -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha" \
  -d '{"requester_id": "operator", "payload": {}}' | jq '{request_id, status}'
```

- DMS `dms-storage-quota` ResourceQuota 오브젝트만 삭제한다. **namespace, PVC, non-DMS
  ResourceQuota는 보존**한다(DMS lifecycle delete ≠ namespace delete).

### 3.6 Consistency Check (`:check`)

DB `desired_state`(hard 키 set)와 live `ResourceQuota.spec.hard` + **metadata**를 대조한다.
side-effect 없음. drift는 `issues[]`로 보고.

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha:check" \
  -d '{"requester_id": "operator", "payload": {}}' | jq '{request_id, status}'
```

검사 대상:

| 항목 | drift 시 issue_type |
|---|---|
| hard 키별 값(`requests.storage`/`persistentvolumeclaims`/각 SC key) | `kubernetes_quota_drifted` |
| ResourceQuota 부재 | `kubernetes_quota_missing` |
| `metadata.labels.dms.io/resource-kind` 불일치 | `kubernetes_quota_metadata_drift` |
| `metadata.annotations.dms.io/resource-key` 불일치 | `kubernetes_quota_metadata_drift` |
| namespace 내 **non-DMS ResourceQuota** 존재(effective quota 영향) | `kubernetes_effective_quota_warning` |

> effective quota 경고: namespace에 DMS 외 다른 ResourceQuota가 있으면 실제 유효 quota는 모든
> RQ의 교집합(가장 엄격한 값)이 된다. DMS는 그 RQ를 변경하지 않고 경고만 남긴다.

### 3.7 Sync Live State (`:sync`)

live `ResourceQuota.spec.hard`를 읽어 DB `desired_state`(`quota` + 각 `storage_class_quotas[]`)로
**역산**해 맞춘다. live 오브젝트는 변경하지 않는다.

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-alpha:sync" \
  -d '{"requester_id": "operator", "payload": {}}' | jq '{request_id, status}'
```

- `requests.storage`/`persistentvolumeclaims` → `quota`로, `<sc>.storageclass.storage.k8s.io/*`
  키 → 해당 `storage_class_quotas[]` entry로 역매핑한다(SC 이름 → storage mapping `storage_name`).

### 3.8 Import 외부 ResourceQuota (`:import`)

이미 namespace에 존재하는 ResourceQuota(또는 사전 생성한 `dms-storage-quota`)를 DMS 관리로 채택한다.

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas/cluster-a/team-beta:import" \
  -d '{
    "requester_id": "operator",
    "payload": {
      "expires_at": "2099-01-01T00:00:00Z",
      "storage_class_quotas": [{"storage_name": "longhorn-a"}]
    }
  }' | jq '{request_id, status}'
```

- live `spec.hard`를 읽어 DB desired로 채택하고, DMS marker(label/annotation)를 부여해 full-managed로
  전환한다. 이후 PATCH/check/sync/block 대상이 된다.
- 이미 DMS가 관리 중(non-Deleted)이면 `kubernetes_namespace_quota_resource_already_exists`로 reject.

### 3.9 On-demand Audit (`:audit`)

여러 namespace의 DMS-managed quota를 **read-only**로 한 번에 점검한다(Kubernetes 변경 없음).
`scope`로 단일 namespace 또는 전체를 지정한다.

```bash
# 단일 namespace
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas:audit" \
  -d '{"requester_id":"operator","payload":{"scope":{"cluster_name":"cluster-a","namespace_name":"team-alpha"}}}' | jq

# 전체(scope 생략 또는 부분 지정)
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas:audit" \
  -d '{"requester_id":"operator","payload":{}}' | jq
```

- DB desired ↔ live `spec.hard` drift, metadata drift(`dms.io/resource-kind` label /
  `dms.io/resource-key` annotation)를 구조화해 result에 담는다.
- 결과는 quota action-required aggregation(최신 audit/check 기반)에 반영된다.

### 3.10 만료 sweep (`:expiration-sweep`)

만료된 namespace quota를 일괄 차단한다(filesystem sweep과 동일 패턴).

```bash
curl -sS "${DMS_CURL_OPTS[@]}" \
  -X POST -H "content-type: application/json" \
  "$DMS_API_URL/api/v1/resource-management/kubernetes/namespace-quotas:expiration-sweep" \
  -d '{"requester_id":"sweeper","payload":{"scope":{"resource_type":"user"},"dry_run":true}}' | jq
```

- `dry_run:true`는 대상/스킵 사유만 보고(side-effect 없음). 실제 실행은 만료 + 차단 가능한
  (`user`/`project`) resource를 `block`한다. `system`/`admin`은 자동 차단 제외.
- `scope.cluster_name`/`scope.resource_type`/`expired_before`로 범위를 좁힐 수 있다.

### 3.11 resource_type / default reset

- `resource_type`(`user`/`project`/`system`/`admin`)은 filesystem과 동일하게 만료 sweep/`:block`
  보호 정책에 영향을 준다(`system`/`admin`은 자동/명시 차단 거부). create/PATCH로 지정·변경.
- `reset_quota_to_default: true`(PATCH/create)는 등록된 default quota policy 값으로 hard를 재설정한다
  (default policy는 `POST /api/v1/resource-management/default-quota-policies`로 등록; 정책 미존재 시
  관련 검증에서 reject).

## 4. Operations 조회 API

```bash
source /mgmt_storage/cocoa.song/.dms-secrets/dms-env.sh

# 단건 조회 (DB desired + live spec.hard + effective warning)
curl -sS "${DMS_CURL_OPTS[@]}" \
  "$DMS_API_URL/api/v1/operations/kubernetes/namespace-quotas/cluster-a/team-alpha" | jq

# 만료된 namespace quota 목록
curl -sS "${DMS_CURL_OPTS[@]}" \
  "$DMS_API_URL/api/v1/operations/kubernetes/namespace-quotas/expiring?status=expired" | jq

# 7일 내 만료 예정
curl -sS "${DMS_CURL_OPTS[@]}" \
  "$DMS_API_URL/api/v1/operations/kubernetes/namespace-quotas/expiring?status=expiring&within_seconds=604800" | jq
```

`/namespace-quotas/expiring` 쿼리 파라미터는 filesystem의 `/filesystems/expiring`과 동일하다
(`status`, `cluster_name`, `within_seconds`, `before`, `include_blocked`, `limit`).
request 조회(`/operations/requests?requester_id=`), 상태값, stuck request `resolve`는
[`2.dms-rm-api-fs.md`](2.dms-rm-api-fs.md) §4.2 / §5와 공통이다.

## 5. 주의 / FAQ

- **namespace는 사전에 존재해야 한다.** DMS는 ResourceQuota만 만들고 namespace는 만들지/지우지 않는다.
- **effective quota**: namespace에 non-DMS ResourceQuota가 있으면 실제 한도는 모든 RQ의 가장 엄격한
  값이다. DMS는 그것을 변경하지 않고 경고만 남긴다(§3.6).
- **decrease guard**로 live `status.used` 아래로는 못 낮춘다 — 먼저 사용량을 줄이거나 PVC를 정리한다.
- **cross-cluster**: `storage_class_quotas[].storage_name`이 가리키는 mapping의 `cluster_name`이
  요청 `cluster_name`과 다르면 reject(한 quota는 한 클러스터/namespace에만 적용).
- filesystem RM과 달리 **LDAP/owner/group 개념이 없다**(quota는 namespace 단위 k8s 오브젝트).
